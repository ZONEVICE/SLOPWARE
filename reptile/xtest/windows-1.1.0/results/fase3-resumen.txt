W4  ARCHIVO BLOQUEADO ................. HALLAZGO (importante, especifico de Windows)
    Peer abre readme.txt en exclusiva (FileShare.None) mientras el host lo modifica.
    - No hay caida (peer ping 200, state live durante y despues).
    - Tras soltar NO converge (probado hasta 121s). El peer informa "live: both copies are identical"
      siendo FALSO (divergencia silenciosa). El log del peer no registra nada.
    - Un cambio en OTRO archivo sincroniza pero NO repara el readme divergente.
    - Solo se repara cuando ese MISMO archivo vuelve a cambiar en el host.
    Causa probable: el peer actualiza su indice/base al estado recibido, pero el rename del temporal sobre
    el archivo bloqueado falla (sharing violation de Windows) de forma silenciosa, dejando indice != disco
    sin reintento. En Linux no ocurre (POSIX permite reemplazar un archivo abierto).

W5  SOLO LECTURA (attrib +R) .......... HALLAZGO (misma raiz que W4)
    Peer con readme.txt en +R; el host lo modifica -> NO converge en 30s, attrib sigue +R, sin caida,
    state "live" (erroneo), log vacio. En Windows no se puede reemplazar un archivo de solo lectura;
    el fallo es silencioso. (En Linux el rename sobre un archivo +R en un directorio escribible si funciona.)
    => W4 y W5 son el MISMO fallo: destino no reemplazable en Windows -> divergencia silenciosa sin reintento.
