M1 nota (asimetria ESPERADA de nombres, documentada en las instrucciones):
  - r0 "ok=False" por 1 "extra": Windows RECORTA el punto final de "trailing." -> queda "trailing"
    (contenido presente, nombre distinto). 8 nombres hostiles tolerados.
  - r2 "ok=False": Linux conserva los 6 nombres que Windows no puede tener (a:b.txt, aux.txt, case.txt,
    pipe|name.txt, quote".txt, what?.txt); el peer Windows nunca los tuvo. Asimetria permanente esperada.
  - OBSERVACION: con nombres incompatibles presentes, el log del peer muestra un CICLO
    "synchronising -> live: identical" cada ~2-3 s (reconciliacion que nunca se estabiliza). No hay caida
    ni error; es el "ciclo de reconciliacion" a vigilar. En los escenarios limpios (M2-M6) no se observa.

M10 CAIDA BRUSCA ..... OK
   Parte A (matar peer Windows, host Linux): el host libera la sesion en 22.8s (~20s esperado); al
     rearrancar el peer, re-sync 201 y re-live 1.0s, reconverge ok.
   Parte B (matar host Windows, peer Linux): el peer pasa a "reconnecting" al instante. Al rearrancar el
     host (UUID NUEVO) el peer pasa a "stopped" -> comportamiento POR DISENO (UUID distinto = host
     reiniciado = parar; no es especifico de Windows). Re-sync explicito -> live 0.9s.
